# 多筆財務初始化契約（#29）

## 版本與計算

新增 schemaVersion=3 存檔，沿用 engineVersion 1.0.0／2.0.0；財務公式不變。Scenario 的 initialDetails={version:1,income:[],expenses:[],assets:[],debt:[]} 保存原始明細，每列 {id,name,amount}；amount 為非負整數分，每類最多20筆、ID類內唯一、名稱1–80字、每列及合計不超過既有1兆分上限。允許空類別（合計0）。現金與租金單列，不混入明細；負債明細合計為全部既有負債，還款排程只是其部分分配，不再增加負債或生活費。

明細合計必須逐分等於 Profile 的 income／expenses／assets／debt；不一致或未知版本明確拒絕。引擎只消費原有 Profile，不將明細視為第二份金額。V1 的支出仍沿用含租金的舊語意；本輪 UI 僅在 V2 啟用新明細，不偷偷升級V1財務模型。

## 操作與還原

摘要優先、展開明細；啟用時按現有彙總建立單列「原有彙總」，不猜測組成。編輯明細即更新摘要；直接編輯摘要則以一列彙總取代該類明細，介面先明示規則。套用前均為草稿，可還原；既有儲存仍須另外按儲存。

舊schema1/2讀取與匯出不變，啟用後按「更新基礎資料」才確認轉成schema3，介面提示先匯出原始備份；事件、引擎、父子關係及原始history不變，不自動覆寫IndexedDB。新建人生在#29使用schema3，接入#28角色後使用schema4；兩者沿用同一明細契約。每次修改保存前一版profile/events/initialDetails；子分支複製明細且不可改初始資料，父方案後改不傳播。財務模型的schema1→2顯式轉換入口維持原規則，混合版本不偷偷重算。

## 數值案例與驗收

收入3,000,000+2,000,000=5,000,000分；生活費1,000,000+1,000,000=2,000,000分，租金1,000,000分，無負債時每月現金流2,000,000分。資產合計20,000,000分只入帳一次。既有負債120,000分、零息12期排程120,000分，每月還款10,000分，現金流減少10,000分而非再計一筆負債／支出。測試比較轉換前後全部月份的快照、JSON還原、歷史與分支隔離、超額／重複ID／版本拒絕，以及取消不改工作。
