# 分項財務顯式遷移（#43）

本頁記錄產品流程；財務契約仍以 ITEMIZED_FINANCIAL_CONTRACT.md 為準。四種事件的指定項目編輯介面由 #44 接續，遷移不代表新增完整事件庫。

## 操作及保存

舊版工作室的「升級分項財務」，以及 schema5 內仍含舊樹時的同名入口，可開啟精靈。先下載完整來源 JSON，使用者確認備份已存在裝置上，再選擇原始人生樹；子方案一併納入，既有 V3 樹不重複遷移。

每個人生的 current 及全部 history 都列為獨立版本。原有明細一對一保留；未啟用明細的舊版本保留彙總，不繼承現在的明細或造型。不依名稱猜薪資／兼職；預設收入分類為未分類／其他，使用者可明確指定。V1 支出不推測租金；V2 租金分列。

每筆還款排程必須明確選擇原負債明細，本金由所選來源扣除，剩餘保留 static。沒有依金額或名稱自動配對。同一來源明細可拆為多筆排程及剩餘固定餘額；不得跨多筆來源合併成一筆排程。配置不足、超過項目／事件上限、無法精確轉換的原利率或不支援資料，皆顯示錯誤並保留舊版工作。

舊版彙總收入事件展開至全部收入來源。只有唯一收入來源或合計為零時，分配在數學上唯一而可直接對應；正額多來源必須逐筆輸入元與分，合計等於原值。不接受指數、負額、三位小數或空字串當零。相同樹內、完整原始財務參數／明細／事件完全相同的版本，可由使用者明確批次沿用配對；資料不同者不可批次猜測。

購屋維持舊價款、自付、利率、期數與停租設定，但必須明確確認沿用舊模型的零費用／零持有成本假設；這不表示實際成本為零。穩定 ID 以樹、原明細、原排程與原事件／目標配對建立，跨版本與子方案保留。歷史中排程後來才加入，或明細後來才啟用，皆允許來源組成改變，不假設歷史與現在相同。

## 預覽及確認

完整候選經既有 domain 驗證，檢查每個 current／history 的所有月份。逐版列出變動月數、首次差異、九欄最大絕對差額、末月差額及逐月差額合計（餘額合計不是額外損益）；逐月表格分頁查看舊／新金額。差額摘要以整數分呈現，明細以元與兩位小數呈現。即使只差一分，仍需明確勾選接受差異才可套用。

確認前不更新 Project，也不寫 IndexedDB。確認協定再次核對整份來源未改變，保留完整原始來源、映射、分支、歷史及既有遷移紀錄。確認後僅替換目前工作並標示未儲存；按「儲存」才寫入本機。重新匯出包含完整 schema5 容器；欲還原舊格式可匯入升級前備份。

取消、Escape 或返回修改皆可丟棄候選，背景操作 inert；取消後還原開啟按鈕焦點。下載只能確認瀏覽器已發出下載，是否成功保存由使用者確認，不能宣稱已自動驗證裝置檔案。

## 驗證界線

單元測試涵蓋整樹選擇、歷史缺明細／缺排程、顯式分配、分位精度、來源未變與 schema5 續遷移。瀏覽器案例涵蓋實際下載、取消／焦點、逐版配對、全月表格、差異接受、工作套用與另存後恢復。實際通過數量及遠端 CI／Pages 證據寫入 VALIDATION.md 與 PR；本頁不代替真人、多瀏覽器或硬體驗收。
