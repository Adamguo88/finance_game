# 開發路徑與優先順序
依依賴關係交付，不依頁面數量計進度。以下每階段對應 docs/ISSUES.json；實際執行紀錄以 VALIDATION.md 為準，未建立 GitHub issue 不標示為已開立。

| 階段 | 優先 | 依賴 | 交付 | 驗收閘門 |
|---|---|---|---|---|
| S0 專案與規格 | P0 | 無 | Next.js TS、README、AGENTS、PRD、架構、roadmap、CI | npm ci、static build |
| S1 財務核心 | P0 | S0 | 型別、金額、月度快照、買房與失業 | 手算基準、邊界、決定性測試 |
| S2 方案與版本 | P0 | S1 | 不可變分支、共同初始快照、歷史與版本 | 父子隔離、歷史鎖定、存檔資料 round trip |
| S3 編輯與體驗 | P0 | S2 | 基礎表單、卡牌編輯、時間軸、SVG | 卡牌影響後續月份；跨模式時間保留 |
| S4 平行比較與存檔 | P0 | S3 | 多場景、同步播放、IndexedDB、JSON | reload/load、無效檔拒絕、同步月驗證 |

## v0.1 發布標準
所有 P0 計算與分支測試通過；三模式完整走通；本地存檔與備份可還原；無未處理 console/page error；支援版本寫明。GitHub repository（finance_game，已授權公開）、issues 與 Codex Cloud 是交付整合項目，若權限不足需明確列出，不能以程式測試通過代替。

## Codex 執行節奏
每次一個階段／issue，先驗收條件再修改。先讀 AGENTS.md，完成後提供 diff 摘要、實測結果、限制。雲端網路只在 npm ci/安裝瀏覽器時使用；應用執行無後端依賴。建置不得依賴線上字型。
