# 開發路徑與優先順序
依依賴關係交付，不依頁面數量計進度。以下階段已建立為 GitHub issues #1–#7：https://github.com/Adamguo88/finance_game/issues 。詳細 title/body 原稿見 docs/ISSUES.json；實際驗證以 VALIDATION.md 與各 issue 的最新驗收紀錄為準。

## 開發優先順序：PC 優先（2026-11-25 使用者指示）

先完成 PC 端全部規劃功能，包含 UI／UX、角色與場景建模及視覺呈現，待 PC 端完整驗收後，再開始 iPad 與手機適配。不能以單一版本、垂直切片或技術展示完成，代替 PC 全功能完成。

- 現階段需求、排程、介面設計、互動與效能優化，以 PC 瀏覽器及滑鼠／鍵盤操作為主；不安排 iPad／手機專屬版面、觸控手勢或裝置優化工作。
- PC 完成條件：已納入產品範圍的功能逐項實作與驗收，核心流程完整，UI／UX 與建模／視覺資產達正式交付標準，且數值、分支、歷史、存檔、桌面互動與效能檢查通過。建模技術與細項依各階段規格確定。
- iPad 與手機的版面、觸控互動、裝置效能及相容性測試統一列入後續適配階段，不作為當前 PC 功能開發或交付的前置條件。
- 已有響應式程式、手機測試與歷史驗證紀錄保留；不以刪除既有能力落實此順序，也不為了行動端擴張目前開發範圍。

## v0.1 發布標準
所有 P0 計算與分支測試通過；三模式完整走通；本地存檔與備份可還原；無未處理 console/page error；支援版本寫明。GitHub repository（finance_game，已授權公開）、issues 與 Codex Cloud 是交付整合項目，若權限不足需明確列出，不能以程式測試通過代替。

## Codex 執行節奏
每次一個階段／issue，先驗收條件再修改。先讀 AGENTS.md，完成後提供 diff 摘要、實測結果、限制。雲端網路只在 npm ci/安裝瀏覽器時使用；應用執行無後端依賴。建置不得依賴線上字型。
