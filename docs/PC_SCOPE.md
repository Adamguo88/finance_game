# PC 全功能範圍與驗收矩陣

Issue #15；更新 2026-11-26（Asia/Taipei）。前置基準 main `5a28284`：#15–#22 與 #29 已合併；本階段已實作 #29 → #28，下一項 #23。這是可追溯的完成定義，不是 PC 全功能完成宣告。

## 原討論與設計基準

已讀取 [研究卡牌財務系統](chatgpt-conversation://6b063fbc-f5d0-83e8-b687-2758ae736e2a) 的 UI/UX 與三模式討論。採用「卡牌作為操作、持續存在的微縮人生世界作為呈現」：溫暖療癒、低多邊形、等角/2.5D 空間、柔和陰影，適合成年到熟齡使用者；不以淨資產排名定義成功。

主要資訊架構：P01 首頁 → P02/P03 逐步建立角色/財務 → P04–P08 共用工作室（上方財務 HUD、中間生活世界、下方時間軸、旁側事件工具）→ P09 回憶錄/報表；P10 管理本機保存及 JSON 備份。體驗模式應收起編輯表單，場景中的住宅/工作/財務區可成為操作入口。

採 2D 可修改向量資產表現 2.5D 視覺；3D、隨機事件、AI、後端仍非當前範圍。參考圖/概念原型不是已驗證規格，不照搬其中簡化公式。角色外觀、完整事件庫、多筆財務明細等明顯差距不能因本輪先做外觀改善而被省略。

## 桌面驗收範圍與預算

- 主要尺寸：1280×800、1440×900、1920×1080，100% 縮放；滑鼠與鍵盤均可完成主要流程。主要資訊不被長表單推離首屏；長時間軸/明細可在自己的區塊捲動。
- 桌面 Chromium/Chrome、Edge、Firefox、macOS Safari 為目標矩陣。現階段 Linux Chromium 自動化不等於 Windows/macOS/Firefox 真人驗證；平台、版本、尺寸、日期與未執行項各自記錄。
- SVG/2.5D 資產階段：原始自製向量模組總計 <=150 KiB，新增 gzip JS <=100 KiB 作初始預算；無遠端字型/圖片；沒有事件動畫時不啟動持續 RAF/ticker。後續 PixiJS 套件成本在 #18 另量測，不混入此預算。
- PC 操作/渲染以合法的 2 MB、20 方案、100 事件/方案上限合成資料量測。記錄測試機、production build、操作耗時與記憶體/迴圈數；互動回應以 100ms 為初始目標，動畫 60fps 為目標，未量測不宣稱達標。資料上限必須同時合法，不能使用超過匯入限制的假負載。
