# 使用者主導的現金缺口選擇（#21）

## 快照說明

負現金仍完整保留。工作室缺口提示提供「檢視缺口選擇」，不自動彈出、不新增隨機危機。視窗顯示當前月份/缺口、連續缺口起點、快照的收入、支出、租金、房貸、其他負債付款與現金變化；現金變化含一次性事件，不能當作純經常性支出。當月啟動事件只列來源排程，不替使用者猜測唯一原因。V1 不虛構拆分租金/負債排程。

## 回溯與分支

「回到缺口前一月」只移動共同時間，回焦到時間軸，不改 Project/歷史。來源是已分支人生時可切回父人生檢視，也不改資料。

選擇名稱及分支點後按「預覽分支」，純 `gap-plan.ts` 使用既有 forkScenario/parseProject/simulateForDisplay 產生可丟棄候選。原人生、其他方案、history、儲存狀態完全不變；輸入變動使舊預覽失效。建立分支本身不改數字，預覽清楚顯示分支點/觀察月/終點的現金與負債，沒有宣稱已修復缺口。

分支點只能在來源的既有 forkMonth（原人生為0）到目前月/人生終點前一月之間，不能透過此流程解鎖來源歷史。若缺口位於既有鎖定區，只能回溯/切來源人生。20 方案上限及2MB候選都經既有驗證，失敗不提交。

## 確認與事件比較

只有按「確認建立分支並規劃事件」才寫入一個新分支，標記尚未儲存，不覆寫 IndexedDB。確認前再次比對 base Project 身分，拒絕過期預覽。分支保留全部原排程、同一引擎/初始參數，歷史與 revision 依既有 fork 契約。

確認後在分支點開啟現有事件庫；事件需另行填參數、檢視 EventImpactPreview、按「儲存事件」才修改分支。取消事件只保留已明確確認的空白分支，不新增事件/歷史。「比較這次選擇」比較原人生與分支的原缺口月份；若來源日後改變共同期間，明示新的比較上限。回載仍取得使用者先前明確儲存的版本，沒有自動存檔。

V1 保留原版，只允許原本支援的事件；V2 薪資/租金仍使用既有規則與預覽。保險、投資、出售、額外借款或其他新財務類型不在本 issue，後續先由 #27 訂數值與版本契約。

## 鍵盤與替代

沿用共有 modal focus trap、Escape、背景 inert 與取消回焦；預覽產生後將焦點/視區移到預覽，確認/事件庫/事件編輯之間不短暫解除背景保護。滿額停用 fieldset 的所有子控制以 :disabled 從焦點列表排除。關閉事件庫/編輯回到穩定的編輯模式按鈕。呈現文字與表格不依賴動畫/音效。

## 驗證

單元測試驗證 V1/V2 不變性、負現金/零負債保留、全部未來排程深拷貝、取消候選、鎖定/非法點/非缺口/名稱/20方案拒絕。桌面 E2E 覆蓋預覽取消與回溯、確認分支再編輯事件/取消/同月比較、原人生不變與本機備份不覆寫、鎖定來源切換、V1 限制與滿額焦點陷阱。財務 domain/公式、版本/遷移與 Project schema 沒有修改。真人多瀏覽器/實機效能/完整 PC 總驗收仍屬 #24。
