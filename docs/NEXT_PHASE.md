## #29：先定財務資料契約

先確定明細欄位、摘要與明細修改規則、租金／負債排程映射及舊彙總存檔轉換；禁止重複計算本金、租金或支出。規格與數值／遷移測試通過後，才接新增、編輯、移除明細及五步建立流程。僅重組輸入時，所有舊月度結果須逐分一致；若改公式，須新增引擎版本。歷史、分支鎖定及原始參數不得丟失。

## #28：再定角色與視覺資料契約

先定版本化 presentation metadata，再實作非敏感造型、色彩及依顯示年齡變化的生命階段；不猜測家庭成員，不改財務 Profile 或計算結果。資料須隨分支、存檔、JSON 備份還原；舊資料有明確預設，未知格式拒絕。使用現有 2D／2.5D 資產與 SVG 備援。

## 階段驗收與交付

- #29：數值、彙總無重複計算、舊存檔轉換、錯誤不覆蓋、父子隔離與完整還原。
- #28：外觀／年齡呈現、預設角色、未知版本拒絕、財務結果不變與備份還原。
- PC 端到端：新建 → 明細 → 外觀 → 播放 → 分支 → 本機保存／JSON 還原；保留全部既有回歸。
- 每項契約先於實作，以可審查 PR 交付，核對最新 head CI；Pages 另行核對。真人結果僅由實際操作記錄，不代填。
- 本階段不啟動行動端、後端、AI、3D 或新財務事件；下一個功能開發入口為 #23，本次交付後不自動啟動。
