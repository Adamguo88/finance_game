# Life Studio

人生，沒有唯一的劇本。自行安排事件、播放人生與同步比較分支，理解財務選擇如何影響未來。純前端 Next.js + TypeScript，資料保存在此瀏覽器的 IndexedDB，支援 JSON 備份。

## 目前開發順序

先完成 PC 端全部規劃功能，包含 UI／UX 與建模，再進行 iPad／手機適配。現階段以桌面瀏覽器、滑鼠／鍵盤與 PC 效能為主；具體完成條件見 [產品規格](docs/PRD.md) 與 [開發路徑](docs/ROADMAP.md)。

## 啟動與檢查

使用 Node.js 24（`.nvmrc`），不需要環境變數或後端服務。

```sh
npm ci
npm test
npm run typecheck
npm run build
npx playwright install --with-deps chromium
npm run test:e2e
npm run dev
```

開啟 http://localhost:3000 。`npm run build` 產生純靜態 `out/`。若使用系統 Chromium，可設定 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`；對靜態伺服器測試時設定 `PLAYWRIGHT_BASE_URL`。

## GitHub Pages

`.github/workflows/pages.yml` 在 main 更新時建置並部署 `out/`，使用 Node.js 24 與官方 Pages artifact/deploy actions。部署建置設定 `NEXT_PUBLIC_BASE_PATH=/finance_game`；本機不設定此變數時仍從根路徑啟動。Pages 的 Source 使用 GitHub Actions，第一次啟用如受權限限制，需倉庫管理者在 Settings → Pages 設定。部署狀態以 Actions 的 Deploy GitHub Pages 工作流程及 github-pages environment 為準。

本機測試子路徑可執行 `NEXT_PUBLIC_BASE_PATH=/finance_game npm run build`，將 out/ 掛載至靜態伺服器的 `/finance_game/`；不要直接以根路徑載入該建置。網站資料仍保存在各使用者瀏覽器，切換網址前請先匯出 JSON 備份。

## CI 與下一階段

CI 只在指向 main 的 PR、push main 或手動 workflow_dispatch 執行；功能分支單純 push 不再重複驗證。Pages 在 main push／手動觸發時獨立部署。詳見 [CI 配置](docs/CI.md)。

## PC 旅程與工作室

首頁可開始五步建立、讀取/匯入存檔，或探索 V1 範例。新建人生採 V2，確認前不改工作、確認後仍須儲存。工作室顯示「表單尚未套用／工作尚未儲存／已儲存至本機」，財務 HUD 在中央世界上方；體驗模式收起編輯工具。流程與儲存語意見 [PC_UX.md](docs/PC_UX.md)。

## 基本操作

1. 在「編輯」填入年齡、現金、其他資產、既有負債、收入與支出，按「更新基礎資料」套用；加入購屋與失業事件。未套用的表單會提示先套用或「還原未套用資料」，以免切換操作遺失草稿。
2. 使用「體驗」播放、暫停、調速與逐月回溯，三種模式共用月份。
3. 從目前月建立分支；分支點以前的事件及初始資料鎖定，只能修改未來事件。
4. 在「平行人生」勾選方案，同月比較場景與財務結果，採最短期間作播放終點。
5. 按「儲存」保存；重新整理後按「讀取」。匯出 JSON 可備份或跨瀏覽器匯入。

## v0.2 財務模型

初始範例及舊存檔仍使用 V1 引擎，結果不會默默改算。按「升級財務模型」先看轉換預覽、下載原始 V1 備份，再確認轉換整個專案。取消或失敗不改工作；確認後仍須另外按「儲存」，不會自動覆寫 IndexedDB。

V2 可設定：

- **生活費與租金分列**：升級時原有支出不變、租金為 0；請自行拆分，不猜測舊支出中的租金。
- **購屋停止租金**：預設不停止，需勾選；購屋當月起生效。同月另有租金事件時，以該事件的新租金為準。
- **調整月租金／正常月薪**：指定月份起換成新金額，直到下一事件。失業期間用替代收入，結束後恢復當時正常月薪。
- **既有負債排程**：將既有負債的一部分分配到最多 20 筆還款排程，沒有新增借款。各筆獨立算息與取整、末期清償。第一付款月之前不累息；未分配部分維持固定。生活費勿再包含這些還款，避免重複扣款。

舊備份以 schema=1 / engine=1.0.0 計算；格式 schema=2/3/4 可容納 engine=1.0.0 與 2.0.0 的不同根方案。同一分支樹須使用相同引擎。升級按鈕可轉換 schema=1 整個專案，以及 schema=3/4 且所有方案仍為 V1 的專案，保留明細與造型；不對 schema=2 的混合專案進行第二次轉換，也不支援降版。需回復時匯入原始備份。

## 多筆財務明細

V2 的基礎資料可「啟用財務明細」，展開收入、生活費、其他資產及既有負債，新增／修改／移除各筆。明細同步加總；直接修改摘要會合併該類明細為一筆彙總。現金、租金及還款排程另列，不要重複填入生活費。套用前可還原草稿，套用後仍須另按儲存。

使用明細時存檔格式升為 schema=3；舊 schema1/2 不會自動改寫，建議先匯出原始 JSON。V1 須先使用既有「升級財務模型」流程，沒有在啟用明細時偷偷改算。契約及數值例見 [INITIAL_DETAILS.md](docs/INITIAL_DETAILS.md)。

## 多軌事件時間軸

目前方案的住宅、職涯、租金及薪資事件各列一軌（V1 僅前兩軌）。編輯模式可拖曳卡片調整整數月份，左右鍵一次一月、Shift＋左右鍵一次一年；點擊或 Enter 開啟既有事件視窗。放開才提交，Escape 可取消拖曳，無效重排保留原資料與歷史。分支點以前事件鎖定，未來事件也不能移入鎖定區。

體驗/比較模式點擊事件只定位月份；比較時軌道顯示目前人生，明標方案名稱。時間軸在區塊內水平捲動，「定位目前月」可移動可視區；原月份滑桿與事件清單仍可使用。既有負債排程留在基礎表單，本輪不拖曳或新增事件類別。操作契約見 [TIMELINE_CONTRACT.md](docs/TIMELINE_CONTRACT.md)。

## PC 事件庫與影響預覽

「瀏覽事件庫」提供住宅／職涯分類及關鍵字搜尋，可先了解所需參數與效果，再開啟設定。V1 不支援的模板、已安排購屋及事件數量限制會明示原因，原快速新增入口仍可使用。

事件設定右側顯示事件當月與 90 歲終點的原方案／預覽現金、負債、淨資產與差額，沿用該方案引擎，其他事件保持不變。取消不改方案；只有儲存事件才套用。清空或輸入無效參數時不顯示過時結果。詳見 [PC 編輯流程契約](docs/EVENT_WORKFLOW.md)。這輪完善現有四類事件，沒有新增財務模型。

## 角色外觀與生命階段

建立人生第一步可選短髮／長髮與森林綠／海洋藍／陶土紅。既有工作在基礎資料按「設定角色外觀」，與財務資料共用套用、草稿還原及分支鎖定；套用後仍須儲存。外觀隨 JSON／本機保存與分支完整還原，選擇外觀時存檔使用 schema4，未知格式明確拒絕。

角色依顯示年齡呈現青年（18–39）、中年（40–64）、熟齡（65–90）；播放、跳月、回溯與比較同步。階段不代表退休、健康或家庭狀態，外觀不影響財務結果。詳見 [角色契約](docs/AVATAR_PRESENTATION.md)。

## 角色與持續微縮世界

角色、住宅、職場、財務小屋及休憩公園使用共用的原創 2D/2.5D 向量資產。工作/休息、租屋/購屋、房貸與缺口依當月快照顯示；點擊住宅、工作或財務區可先查看明細，再進入對應規劃。模型圖鑑位於 `/scene-gallery/`，可修改的獨立 SVG 與 manifest 在 `public/art/models/`，來源與規格見 [WORLD_ASSETS.md](docs/WORLD_ASSETS.md)。

## 財務邊界

金額為新臺幣分的整數，畫面保留到分。單一房屋、固定房價與利率；無稅費、通膨、投資報酬、出售房屋或提前還款。負現金顯示缺口，不自動借款或模擬違約。

V1 的既有負債不攤還、生活費固定、購屋不自動取消租金；這些舊語意完整保留。V2 不猜測任何缺少的財務條件，結果僅反映使用者設定。
